1. Foundational Architecture: What is Tier-1 Backbone vs. Tier-2 Regional?

Why this architecture is required (The Core NLP Challenge): There are zero public, labelled sentiment datasets for Maharashtra's rural spoken dialects (such as Ahirani, Varhadi, Malvani, or Deshi). Manually annotating 50,000 sentences from scratch is practically infeasible. To solve this in an academically rigorous manner, this project establishes a Two-Tier Architecture:

Tier-1: "The Backbone" Training Foundation

Volume: 67,500 Rows (Standard Marathi + Konkani)

  • What it is: High-resource curated datasets (L3Cube-MahaSent-MD, sea-rod Konkani, and AI4Bharat IndicSentiment).
  • Role in Project: Serves as the Training Set for Parameter-Efficient Fine-Tuning (LoRA & 4-bit QLoRA).
  • Purpose: Teaches the base Large Language Model foundational Devanagari grammar, Marathi sentence structure, and positive/neutral/negative sentiment patterns.

Tier-2: "The Regional Dialects" Evaluation Benchmark

Volume: 300 Rows (100% Native-Speaker Verified)

  • What it is: Authentic spoken dialect comments and transcriptions from 5 Maharashtra cultural regions (Ahirani, Varhadi, Malvani, Marathwada, Deshi).
  • Role in Project: Serves as the Final Exam / Holdout Test Suite (60 samples per region). The model never trains on this.
  • Purpose: Evaluates zero-shot cross-dialect transfer: "Can an LLM trained on Standard Marathi generalize to understand rural regional spoken dialects?"
Faculty Guide Script: "Sir/Ma'am, because no dialect sentiment corpora exist for rural Maharashtra, we designed a Two-Tier methodology: We train the LLM on 67.5k Standard Marathi & Konkani samples (Tier-1 Backbone) using LoRA/QLoRA, and evaluate its ability to generalize on 300 newly collected, human-annotated sentences across the 5 cultural regions of Maharashtra (Tier-2 Regional Benchmark)."

5. Complete Preprocessing Pipeline (Step-by-Step)

All raw text underwent a 6-stage preprocessing pipeline designed specifically for Large Language Model instruction tuning:

1 Unicode NFC & Devanagari Normalization

Applied unicodedata.normalize("NFC", text) to unify Devanagari composite glyphs, matras, and virama sequences. Resolved inconsistent Unicode encodings between Android mobile comments, web scraping, and transcription files. Multiple spaces, tabs, and carriage returns were collapsed into clean single spaces.

2 Noise, Spam & Artifact Filtering

Stripped raw URLs (http/https), HTML character entities (&amp;, &lt;, &gt;), YouTube timestamp references (e.g., 02:15, 12:44), user mentions, and corrupted ASCII noise. Removed non-Devanagari spam comments while preserving valid regional code-switching.

3 3-Class Sentiment Schema Unification

Raw datasets had incompatible labels: MahaSent used +1 / 0 / -1, IndicSentiment used POS / NEG, and friend annotation sheets used strings. All 67,800 records were harmonized into exactly three categorical target tokens: positive, negative, and neutral. Verified 0 missing, null, or out-of-schema labels.

4 Strict Deduplication & Contamination Audit

Performed exact-match text deduplication within splits. Ran cross-split string matching between the 300 Tier-2 dialect evaluation rows and the 51,846 training rows. Confirmed exactly 0 training-test overlap, ensuring 100% test integrity without data leakage.

5 LLM-Specific Preprocessing Rules (Why Emojis & Stopwords Were Preserved)

Unlike traditional TF-IDF / SVM models, modern LLMs (Mistral-7B, Llama-3, Qwen) require natural sentence syntax. We intentionally did NOT remove stopwords or punctuation:
• Negation particles (e.g., नाही, नको, कधीच नाही) are essential for determining sentiment polarity.
• Emojis (e.g., ❤️, 😊, 😂, 😡) convey decisive emotional signal in regional comments and are natively supported by LLM tokenizers.

6 Sequence Length & Token Truncation Analysis

Audited token word lengths across Marathi splits: 95% of sentences contain $\le 40$ words. A uniform maximum sequence length of max_seq_len = 256 was configured in tokenization scripts, guaranteeing 100% of sentences fit within context without truncation loss or memory OOM.
